# M3 Evidence — Business & Product Skills

Review material for the M3 human gate. Nothing here marks M3 complete.

## How the evidence was produced

- **Skills under test:** `create-brd`, `create-prd`, `create-stories` (`skill-library/skills/`), the shared method `skill-library/shared/interview.md`, and the unchanged M2 CLI.
- **Agent runs:** real headless sessions in throwaway projects, with Skills installed through the M2 adapters (`install/claude_code.py --scope project`, `install/codex.py --scope project`) and `python -m sdlc` from a Python 3.11.16 environment with the library installed editable. Claude Code used `claude -p` (`-c` to continue); Codex used `codex exec` and `codex exec resume --last`. The human side of each conversation was scripted by the author of this report; the words in the transcripts under "USER" are exactly what was sent.
- **Snapshots:** the resulting projects are stored in `skill-library/tests/fixtures/m3/<scenario>/`, full transcripts in `skill-library/tests/fixtures/m3/transcripts/`. `tests/unit/test_m3_fixtures.py` asserts properties of every fixture. Fixtures are agent output: they are not regenerated by the test suite, and re-running an agent will produce different wording.
- **Fixture setup that was *not* agent output** (stated in the transcripts): in `approved-revision`, BR-001, US-003 and US-001 were set to `Approved` with `created/updated: 2026-09-01` before the revision requests, simulating earlier human approval and making the `updated` change observable.

## Adaptive interrogation (excerpts)

Scenario 1, round 1 — the agent initialized, checked overlap (none), and asked problem-first questions, no solution talk, no files:

> Now let's get into it. I'll ask a first batch of questions focused on the problem and outcomes; feel free to say "unknown/TBD" on any. 1. Who's the driving stakeholder…? 2. What does success look like? … any target numbers, or TBD? 3. Scale/context … 4. Reminder channels … 5. Any known constraints already — budget, timeline, regulatory…

The user answered with `TBD`/unknowns ("Success target: TBD… I don't know which [privacy rules]"). Round 2 **adapted**: it did not re-ask stakeholders, problem or success, and moved to scope-boundary questions the answers opened (data source, two-way vs one-way, timing, consent, out of scope). Round 3's draft carried the unknowns visibly:

> Reduce appointment no-show rate (target: **TBD**) … Which specific privacy/data regulations apply (e.g., HIPAA) … Open Questions / TBDs … Whether reminders will be one-way … Let me know what to adjust — or say "write it".

The user asked for one change ("R004 shouldn't name HIPAA"); the written BRD (`brd-standalone/BR/BR-001-…`) dropped it, kept `Target: TBD`, `Budget: TBD`, and eight Open Questions with `Owner: Unknown`. No target percentages were invented.

Scenario 2 — the agent found BR-001 unprompted and asked, "should this PRD be derived from BR-001? If yes, I'll skip re-asking about the underlying business problem/stakeholders and focus on product-level decisions the BRD left open." (`s2-prd-with-brd.md`).

Scenario 4 — before drafting, the agent noticed behavior in the PRD with no requirement ID and refused to invent one:

> Two things in the PRD's Behavior/Scope section have **no requirement ID** to cover… I don't want to invent requirement IDs for these. Options: (a) fold them into Story 5… (b) write them as a standalone story (`covers: []`)… (c) flag it back to you to add as new PR requirements first (via create-prd).

Codex (`c1-codex-prd.md`) produced a draft that separated **Proposed** rules ("Proposed conflict rule…", "Working assumption") from user decisions and listed 5 open questions and 3 "material tradeoffs" before any file existed.

## Overlap handling

`s6-overlap.md`: with BR-001 present, a new-BRD request on the same topic produced, before any allocation:

> There's already a draft BRD for this exact topic: **BR-001**… do you want to: 1. **Revise/extend BR-001**… or 2. **Start a fresh BRD**…? I won't write or allocate anything until you've reviewed a draft.

The ledger was unchanged at that point. **Branch A (revise):** the agent proposed a diff, and flagged that the requested opt-out overlapped the existing BR-001-R005 and offered "(a) new requirement / (b) fold into R005" — it then applied (a): BR-001-R006 and R007 allocated, R001–R005 unchanged, no new document (`overlap-revised`). **Branch B (new):** the user chose a new, distinct vendor-side BRD; BR-002 was allocated only then, linked to BR-001 under Related To, BR-001 untouched (`overlap-new`).

## Observed quality issues (for the human reviewer)

- **Interview summaries:** `shared/interview.md` asks for a brief summary of decisions between rounds. Claude's round 2 in scenario 1 did not give one before asking the next questions (it did adapt). The draft step did summarize. Codex's transcript has only one question round before its draft, so this was not observable there.
- **Overlap display:** the Skills say to show CLI candidates with score and reasons. The agents paraphrased ("There's already a draft BRD for this exact topic") without quoting the score/reasons.
- **`prd-standalone`:** one Acceptance Expectation ("No two members can unknowingly add the same item…") was inferred from the user's "bought twice" remark rather than stated, and one behavior sentence is garbled ("…including who is shown as having added it is not yet decided"). Not corrected because fixtures are unedited agent output.
- **Harness note:** `codex exec resume` has no `-s` flag (used `-c 'sandbox_mode="workspace-write"'`). One Codex run was cut off by the harness's output pipe after `allocate-id` but before writing; the next turn reused PR-001 correctly (`c1-codex-prd.md` shows both).

## Post-M3 hardening

### 1. `sdlc init` installs `AGENTS.md` and `CLAUDE.md` (create-if-missing)

Templates are packaged in `skill-library/sdlc/templates/`; `init` writes each to the project root only if nothing exists at that path (exclusive create; files, symlinks and dangling symlinks all count as existing and are left untouched). Regression tests (`tests/unit/test_init.py`): both files created with template content and reported under `created`; existing files preserved byte-for-byte and reported under `existing`; only the missing one created; symlink and dangling-symlink targets untouched and nothing created through them; repeat `init` leaves bytes and mtimes unchanged even after a user edit; a deleted file is recreated without touching the other; `init` from a nested directory targets the project root; instruction files are invisible to maps and `validate`; package data declared; a regular (non-editable) install ships the templates (`test_non_editable_install_ships_instruction_templates`, opt-in).

### 2. Contextual overlap review

After the CLI check and before `allocate-id`, each creating Skill now has the agent list the category (`python -m sdlc list --category X`), read titles, purposes and the map summaries, and present judged overlaps **separately** as *Conceptual overlaps (my judgement, not CLI-scored)* with no numeric similarity, then ask **revise / relate / create new**. The CLI scores are lexical, so all three requests below score under the threshold (pinned in `test_contextual_review_covers_what_the_lexical_cli_misses`) yet the agents caught each one:

| Skill | Request | CLI | Agent (Claude Code) | Transcript |
|---|---|---|---|---|
| create-brd | "Automated appointment reminders for independent clinics" | `No plausible overlaps found.` | Conceptual overlap **BR-001** — "same purpose in different words", quoting its purpose; three-way choice; nothing allocated | `h1-contextual-brd.md` |
| create-prd | "Patient notification service for clinics" | none | Conceptual overlap **PR-001** — same channels, audience and trigger; three-way choice | `h2-contextual-prd.md` |
| create-stories | "Front desk confirms a patient received the reminder" | none | Conceptual overlap **US-005** — same purpose, already covers PR-001-R006; asks what distinct scope, if any, justifies a new Story | `h3-contextual-stories.md` |

`h1` continued with **relate**: BR-002 was allocated only after the choice, links BR-001 under `### Related To`, BR-001 stayed byte-identical to the fixture, and `validate` reported 0 errors, 0 warnings, 0 notices. No score, percentage or level appears in any conceptual-overlap presentation (asserted for `h1`). Only the Claude Code runs were repeated for this hardening; Codex behavior for the contextual review has not been exercised live.
